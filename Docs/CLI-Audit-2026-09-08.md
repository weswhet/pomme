It covered command discovery, help, output modes, argument validation, VM creation and lifecycle, guest execution, jobs, file transfer, UI automation, snapshots, access controls, security workflows, MDM validation, and configuration/IPSW commands.

## Issues discovered

### 1. `jobs wait` loses the completed process status

**Status: FAIL**

Detached execution, job listing, inspection, and log retrieval worked. Waiting did not:

```text
rtk pomme exec pomme-audit-tahoe-0908 --detach --format json -- /bin/sh -c 'sleep 2; echo detached-job-ok'
job: 16a38f08-c755-4815-8643-53a5d7097cb4

rtk pomme jobs wait pomme-audit-tahoe-0908 16a38f08-c755-4815-8643-53a5d7097cb4 --timeout 5 --format json
exit 1
The VM helper returned an invalid response: Missing background job exit status.
```

The same error occurred when waiting after the job had already completed. `jobs inspect` and `jobs logs` returned the exit frame and `exitCode: 0` for that job, so the failure is specific to the wait response path. The advertised guest capability includes `process.wait`; the CLI parser that reports this error is in [PommeGuestJobWait.swift](../Sources/PommeCLI/GuestAgent/PommeGuestJobWait.swift).

### 2. The first SIP disable attempt can fail on malformed owner evidence

**Status: FAIL on first attempt; RESUMED successfully**

On a fresh Tahoe VM, this command reached owner creation and then returned exit 1:

```text
rtk pomme sip disable pomme-audit-tahoe-0908 --force --final-state stopped --format json --debug
Error: Normal guest apfsUsers evidence was malformed. Resume the retained security operation with `pomme sip disable 'pomme-audit-tahoe-0908' --final-state stopped` after resolving any reported cleanup or restoration failure; the operation and final state must match the retained transaction.
```

The VM was stopped, the provisioning agent remained healthy, and `agent repair` correctly refused to alter the security transaction. Repeating the same action with the documented final-state form then completed successfully and reported `configuredDisabled: true`, `normalBootVerified: true`, `runtimeConfigurationVerified: true`, and `enforcementVerified: true`.

The supported resume path recovers the operation, but the initial command still returns a failure after it has already performed owner preparation and retained a durable transaction. This is an intermittent or state-sensitive security workflow failure.

### 3. AMFI disable can hang after booting the normal guest

**Status: FAIL / HANG**

The AMFI status command passed and verified `amfiDisabled: false`, `amfiBootArgActive: false`, and `bootPolicyAllowsCustomBootArgs: true`. The disable command did not return:

```text
rtk pomme amfi disable pomme-audit-tahoe-0908 --force --final-state stopped --format json --debug
```

Debug logging reached:

```text
pomme-audit-tahoe-0908 Booting normal macOS for the journaled AMFI boot-argument change.
```

After more than twelve minutes, `pomme status` reported `vmState: stopped` and `helperRunning: false`, while the `pomme amfi disable` process was still alive. The test process was terminated to avoid leaving an orphaned CLI process. No success or structured failure result was produced, and the AMFI enable path was not attempted afterward because the transaction had been left in the retained state.

### 4. `create --resume` rejects an interrupted provisioning phase

**Status: FAIL**

The second disposable VM completed image installation and reached the Recovery capability probe. Its creator was stopped after the probe so the documented resume path could be tested. The VM bundle was present and stopped, but:

```text
rtk pomme create pomme-audit-recovery-0908 --resume --format json --debug
Error: Pomme provisioning journal has an invalid phase transition.
```

This means the public resume option does not accept the interrupted phase observed during this audit. The initial creator had not emitted its final completion record, so the slow initial creation itself is not counted as a separate failure; the resume result is the reported issue.

## Documented capability and environment blocks

## Retested areas that now pass

The following failures from the previous audit were retested against the current signed build and passed:

- Zero-byte `--disk-size` and `--memory` values are rejected during validation.
- A cached local `--restore-image` resolves successfully in dry-run mode.
- Guest `--cwd`, repeated `--env`, user/group identity, and guest stdin/stdout/stderr redirection are applied correctly.
- Explicit and interactive PTY output includes the child process output.
- Job list, inspect, logs, and signal operations work; `jobs wait` remains the exception described above.
- Host-to-guest, guest-to-host, and guest file reads work, including offset/count reads.
- UI omitted-target parsing works, and ambiguous key sequences now produce an explicit `--vm` disambiguation error.
- Snapshot create, list, forced restore, and delete work. Recorded disk and auxiliary-storage drift produces the documented warning.
- Snapshot appears in root help, `tools`, and `agent-help`.
- A clean VM reports that `agent repair` has nothing to repair.
- Fractional, zero, and over-limit MDM timeouts are rejected as CLI validation errors.
- Recovery screenshot after display settling and Recovery key/click/type input work.
