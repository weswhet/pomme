## CA trust preparation findings

Source inspection found that Pomme's guest enrollment path imports the PKCS12
identity and installs the MDM payload, but does not install the profile's root
certificate payload. The lab therefore needs to establish trust in the local
server CA before enrollment. The profile root was independently checked against
the server project's public root certificate.

An initial `security add-trusted-cert` invocation placed a Pomme output option
after the guest command separator and printed command usage without installing
trust. The corrected guest command ran as root but failed with:

```text
SecTrustSettingsSetTrustSettings: The authorization was denied since no user interaction was possible.
```

A temporary guest-only helper completed administrator authentication but its
trust installation call failed with status `-60007`. A bounded attempt to use a
root-only trust authorization rule was denied with SIP enabled and again with
SIP disabled. Neither attempt installed the CA through that route. The original
authorization rule was verified semantically unchanged. The durable restoration
backup, script, and rescue job were then removed.

Pomme's SIP disable and enable workflows both completed with verification of the
configured state, enforcement, normal boot, and final run state.

A native trust request in the owner's GUI session displayed the expected System
Certificate Trust Settings prompt. Authentication completed successfully, and a
guest HTTPS request without a certificate-verification bypass returned NanoHUB
version `v0.2.0`. Approval credentials passed through the signed CLI and process
memory; they were not printed or written to diagnostic files or logs. Temporary helper, CA,
and terminal artifacts were removed. The clone was stopped with stop method
`guest-stopped`, SIP enabled, and its original authorization rule intact before
the primary enrollment test.

## Open findings

- The enrollment helper failed without enough stage diagnostics to identify the
  cause. The private selector availability check passed, but the root cause
  remains unresolved. This lab does not qualify macOS 27 MDM enrollment.
- Pomme does not install the enrollment profile's root certificate payload. This
  private-CA server required separate guest trust setup and native approval.
- The shared automatic-login credential decoder cannot handle the observed
  nonzero padding after the first NUL terminator. The host decoding path failed
  after removing trailing zero bytes before strict UTF-8 decoding; decoding
  through the first NUL succeeded in the helper and native approval preparation.
  No production repair was made in this lab.

No protected template was modified. No production source changes were made for
this enrollment experiment.
